# 시작 전 준비사항

### "컴이 망가질까"에 대한 답 — 걱정 안 하셔도 되는 이유

멀티부팅 작업 자체가 **하드웨어를 물리적으로 망가뜨리는 일은 없어요.** 실제로 벌어질 수 있는 사고는 딱 두 종류고, 둘 다 "고장"이 아니라 "복구 가능한 실수"예요.

1. **파티션 실수**: Arch 설치 중에 윈도우 파티션을 잘못 골라서 포맷 → 윈도우 데이터/설치 자체가 날아감
2. **부트로더 꼬임**: Arch의 GRUB이 윈도우 부트 항목을 못 찾거나, 반대로 부팅이 아예 안 됨 → 이건 복구 USB로 대부분 고칠 수 있는 수준이지 컴퓨터가 벽돌 되는 게 아님

즉 최악의 시나리오도 "재설치/복구" 선에서 끝나지, 물리적 손상은 없습니다. 
다만 사이툴 작업물이 걸려있으니 **시작 전에 반드시**:

- 그림 작업물 + 중요 파일 → 외부 SSD로 백업 (지난번 얘기한 그대로)
- 윈도우 복구 USB 하나 만들어두기 (문제 생겨도 윈도우만 그대로 복구 가능)

이 두 개만 해두면 "최악이어도 그림 작업 지장 생기는 일"은 사실상 막아지는 셈이에요.

### 윈도우(SAI+유튜브)를 그대로 안정적으로 유지하는 법

Arch를 설치해도 **기존 윈도우 파티션 안의 내용물(SAI, 드라이버, 설정)은 전혀 건드리지 않아요.** 파티션을 분리해서 설치하는 거라 윈도우 쪽은 "존재하던 그대로" 남습니다. 다만 이 부분들만 지켜주면 안전해요:

- **파티션 축소는 윈도우 자체 디스크 관리(Disk Management)에서 먼저 하기** — Arch 설치 프로그램에서 축소하지 말고, 윈도우에서 미리 "볼륨 축소"로 여유 공간(빈 파티션)을 만들어두고 시작하는 게 훨씬 안전
- **Fast Startup(빠른 시작) 끄기** — 켜져 있으면 윈도우가 디스크를 "잠금" 상태로 남겨서 Linux 쪽에서 파티션 문제 일으킬 수 있음
- Arch 설치 시 파티셔닝 단계에서 **디스크 이름/용량을 두 번 세 번 확인** (윈도우 파티션과 새로 만든 빈 공간을 헷갈리지 않기)
- GRUB 설치 후 재부팅했을 때 윈도우 부팅 항목이 안 보이면 당황하지 말고 `os-prober` 활성화나 `update-grub` 재실행으로 대부분 해결됨

이렇게 하면 SAI+유튜브 동시 구동 같은 윈도우 쪽 사용성은 설치 전후로 전혀 달라지지 않아요. Arch는 그냥 "옆에 하나 더 생기는 것"이지 기존 윈도우 성능/드라이버에 영향 안 줍니다.

### 파티션 배분 (단순화 버전)

- 기존 윈도우: 그대로 유지
- Arch용 빈 공간: 60~100GB 정도면 연습용으로 충분 (자료 저장 안 하고 시스템만 깔 거면 40GB도 가능)
- swap: swapfile로 8~16GB 정도




# 디스크 상태 체크하기

### 먼저 확인할 것: C:와 F:가 같은 물리 디스크인가, 다른 디스크인가

디스크 관리(Disk Management, `Win+X` → 디스크 관리)를 열어보면 아래쪽에 "디스크 0", "디스크 1" 이런 식으로 나뉘어 보일 거예요.

- **C:와 F:가 "디스크 0" 하나에 같이 있다** → 물리적으로 한 드라이브 안에서 파티션만 나눈 것
- **C:는 "디스크 0", F:는 "디스크 1"로 따로 있다** → 물리적으로 완전히 분리된 두 개의 드라이브 (SSD + HDD 조합일 가능성 높음, 지난번에 F가 HDD라고 하셨던 것과 일치)

이 경우가 훨씬 흔하고, 이전에 "1TB짜리가 HDD"라고 하신 걸 보면 **아마 C: = SSD(윈도우+SAI 설치용), F: = HDD(데이터용 1TB)** 구조일 가능성이 높아요.

### 만약 물리적으로 분리된 디스크라면 → 훨씬 좋은 상황

이러면 **C:(윈도우 시스템 드라이브)는 아예 안 건드리고, F: 드라이브 안에서만 공간을 만들어 Arch를 설치**하면 됩니다. 즉:

- C: 파티션 축소 자체를 할 필요가 없음 → 윈도우/SAI가 깔린 드라이브는 파티션 테이블조차 안 건드림
- F:(1TB) 안에서 디스크 관리로 볼륨 축소 → 예: 100~150GB 정도 "미할당 공간"으로 빼두기
- 그 미할당 공간에 Arch 설치

이 방식이 지난번에 제가 말씀드린 "C: 축소" 방식보다 **리스크가 훨씬 낮아요.** 애초에 윈도우가 설치된 디스크를 건드릴 일이 없으니까, 파티션 실수로 윈도우가 날아갈 확률 자체가 사실상 0에 가까워집니다.

부트로더(GRUB)는 UEFI 시스템이면 보통 공용 EFI 파티션(보통 C: 있는 디스크에 있음)에 설치되는데, 이건 "새 부팅 항목 하나 추가"하는 개념이라 C: 파티션 내용 자체를 바꾸는 게 아니에요. 다른 디스크(F:)에 있는 Arch도 정상적으로 부팅 목록에 뜹니다.

### 만약 같은 물리 디스크라면

이 경우엔 F: 볼륨을 축소해서 그 안에 여유 공간을 만들고 거기에 설치하면 되는데, C:보다는 F: 쪽 공간을 쓰는 게 여전히 낫습니다 — F:가 데이터 드라이브라 시스템 파일이 없으니 실수해도 영향 범위가 작아요.

---

디스크 관리 화면에서 "디스크 0 / 디스크 1"이 몇 개로 나뉘어 보이는지, 그리고 F:가 GPT/MBR인지만 확인해서 알려주시면 그에 맞춰 정확한 파티션 나누기 단계를 짜드릴게요.



### 지금 구조 해석

- **디스크 0 (111.79GB, 파티션 3개)** → 이게 윈도우 시스템 디스크예요. 파티션 3개는 보통 `EFI 시스템 파티션 + MSR(예약 파티션) + C:` 조합이라, **UEFI 방식으로 설치된 윈도우**라는 뜻입니다. (지난번에 C:가 142GB라고 하셨던 것과 숫자가 안 맞는데, 아마 그때 어림잡아 말씀하신 거고 지금 디스크 관리에서 본 111.79GB가 정확한 값일 거예요)
- **디스크 1 (931.51GB)** → 이건 물리적으로 완전히 분리된 별도 드라이브고, F:로 잡힌 데이터 드라이브네요.

즉 C:와 F:는 **서로 다른 물리 디스크**입니다. 지난번 답변에서 말씀드린 "분리된 디스크면 더 안전하다"는 케이스에 해당해요.

### 그래서 결론: 디스크 0(윈도우)은 절대 안 건드림

- Arch는 **디스크 1(931GB, F:)** 안에서만 공간을 만들어서 설치하면 됩니다.
- 디스크 관리에서 F: 볼륨을 우클릭 → "볼륨 축소" → 100~150GB 정도를 "미할당 공간"으로 빼두세요.
- 디스크 0은 파티션 개수도, 내용도 전혀 손대지 않아요 → 윈도우+SAI 쪽은 설치 과정 내내 리스크 제로에 가깝습니다.

### 부트로더는 어떻게 되나

GRUB(Arch 부트로더)은 새로 만드는 게 아니라, **디스크 0에 이미 있는 EFI 시스템 파티션에 항목만 하나 추가**하는 방식으로 설치됩니다. 즉:

- 디스크 0의 EFI 파티션 자체는 그대로 유지 (기존 윈도우 부팅 항목 안 지워짐)
- 그 안에 "Arch Linux" 부팅 항목이 하나 더 생기는 것
- 실제 Arch 시스템 파일(루트 파티션)은 디스크 1(F:)에 있어도 전혀 문제없이 부팅됨 — 디스크가 물리적으로 달라도 UEFI 부팅엔 지장 없어요

### 한 가지만 확인해주세요

디스크 관리에서 **디스크 1(F:)이 GPT인지 MBR인지**만 확인해주시겠어요? (디스크 1 이름 위에서 우클릭 → 속성 → 볼륨 탭에 "파티션 유형"으로 나와요, 또는 `diskpart` → `list disk`에서 GPT 열에 `*` 표시 여부로 확인 가능)

- GPT면 그대로 진행하면 됩니다.
- MBR이어도 사실 큰 문제는 없어요 (디스크 0이 UEFI/GPT라 부팅 자체는 거기서 처리되니까요). 다만 나중에 파티션을 여러 개로 쪼갤 때(루트+스왑 등) MBR은 파티션 개수 제한(주 파티션 4개)이 있어서 살짝 번거로울 수 있는 정도예요.

=> 대상 PC는 무려 디스크 0도 1도 MBR 인 구식이여서 아래처럼 진행하기: 

레거시 BIOS + MBR 환경에서 GRUB은 EFI 파티션이 아니라 **디스크의 맨 앞부분(MBR 부트섹터)에 직접 설치**됩니다. 그래서 기존 방식(GRUB이 윈도우 부팅 항목도 같이 관리)을 쓰려면 디스크 0의 MBR 부트섹터를 GRUB 것으로 덮어써야 해요. os-prober로 윈도우를 자동 감지해서 메뉴에 추가해주긴 하지만, "디스크 0의 부트코드를 건드린다"는 점에서 지난번 UEFI 가정보다 리스크가 한 단계 올라갑니다.

### 그래서 추천하는 더 안전한 방법: GRUB을 디스크 0에 아예 안 깖

두 물리 디스크가 완전히 분리되어 있다는 걸 이용해서, **GRUB을 디스크 1(F:)의 MBR에만 설치**하고, 디스크 0(윈도우)의 부트섹터는 원래 상태 그대로 두는 방법이 있어요.

그러면 평소엔:

- 그냥 켜면 → 디스크 0 부팅 → 윈도우 그대로 (완전히 원래대로, 아무 변화 없음)
- 아치 쓰고 싶을 때 → 컴퓨터 켤 때 **부팅 메뉴 키**(보통 F8, F11, F12, Esc 중 하나 — 메인보드 제조사마다 다름, 화면에 "Boot Menu" 안내 나오는 경우 많음) 눌러서 "디스크 1(또는 Arch라고 뜨는 항목)" 선택 → 아치 부팅

이 방식의 장점:

- **디스크 0(윈도우) 부트섹터를 단 한 번도 건드리지 않음** → 실수해도 윈도우 부팅에 영향 제로
- Arch 설치/삭제/재설치를 아무리 반복해도 윈도우 쪽은 전혀 영향 없음 (나중에 아치 지우고 싶으면 그냥 디스크 1만 포맷하면 끝, 윈도우는 원래대로)

단점은 매번 부팅할 때 "메뉴 선택" 한 단계가 추가된다는 것 정도인데, 지금 상황(처음 해보는 거라 안전 최우선)엔 이 방식이 훨씬 나아요. 나중에 익숙해지면 GRUB이 둘 다 관리하는 통합 메뉴 방식으로 바꿔도 됩니다.

### 확인해주실 것

메인보드 부팅 메뉴 키가 뭔지 확인해야 하는데, **메인보드 제조사(또는 완제품이면 브랜드명)** 를 알려주시면 정확한 키를 알려드릴게요. (컴퓨터 켤 때 화면 하단에 "Press F11 for Boot Menu" 같은 문구가 스치듯 지나가기도 하니 한 번 재부팅하면서 봐도 됩니다.)



# 부팅 방법

### 기가바이트 보드 부팅키

- **한 번만 부팅할 디스크 고르기 (부팅 메뉴)**: `F12`
- **BIOS/UEFI 설정 화면 들어가기**: `Del` (일부 구형 보드는 `F2`인 경우도 있음)

거의 대부분의 기가바이트 보드가 이 조합이라, 나중에 아치 부팅하고 싶을 때 켜자마자 `F12` 연타하면 "Boot Menu"에서 디스크 1(또는 Arch UEFI/MBR 항목) 골라서 부팅하면 됩니다.

### sys정보(msinfo32)에서 추가로 볼 수 있는 것

`Win+R` → `msinfo32` 입력하면 나오는 "시스템 정보" 창에서:

- **BIOS 모드**: `Legacy`인지 `UEFI`인지 여기서 바로 확인 가능 (아까 디스크 관리로 확인한 MBR과 일치할 거예요 — Legacy로 나올 겁니다)
- **베이스보드 제품**: 정확한 보드 모델명 (예: B450M DS3H 같은 식) — 이게 있으면 정확히 몇 세대 BIOS인지 확인해서 부팅키가 진짜 F12 맞는지 100% 확정 가능
- **BIOS 버전/날짜**: 너무 오래된 BIOS면 USB 부팅 자체가 까다로울 수 있어서 참고용으로 봐두면 좋음

혹시 "베이스보드 제품" 항목도 뭐라고 나오는지 알려주시면, 그 모델 기준으로 부팅키/BIOS 진입키를 정확히 확인해드릴게요.


- **BIOS 설정 화면 진입**: 전원이 켜질 때 POST 화면에서 Delete 키를 눌러 BIOS Setup 프로그램에 접근합니다. [Tom's Hardware Forum](https://forums.tomshardware.com/threads/how-to-open-ufei-bios-on-gigabyte-h110m-s2h.3015217/)
- **부팅 메뉴(한 번만 디스크 선택)**: `F12` — 기가바이트 보드 공통 규격이라 이 모델도 동일하게 적용됩니다.

즉:

- 컴퓨터 켜자마자 **F12 연타** → 부팅 메뉴에서 원하는 디스크(윈도우가 있는 디스크 0 / 아치가 있는 디스크 1) 선택
- 설정 값 자체를 바꾸고 싶을 때(예: USB 부팅 순서 조정, Secure Boot 옵션 등)는 **Delete** 키로 BIOS Setup 진입

한 가지 참고할 점: 검색 중에 이 H110 시리즈 보드에서 **Secure Boot 활성화 시 부팅 루프가 걸렸다는 사용자 사례**가 있었어요. 지금 계획에선 Secure Boot는 어차피 꺼둔 채로(Legacy/MBR 환경이니) 진행하면 되니 큰 문제는 아니지만, 혹시 나중에 UEFI 모드로 전환을 시도하게 되면 Secure Boot는 건드리지 말고 꺼둔 상태를 유지하시는 걸 추천드려요.

| **0. 사전 준비**    | 그림 작업물 등 백업 + 윈도우 복구 USB 만들기                                            |
| **1. 공간 확보**    | 디스크 관리에서 F: 볼륨 축소 → 미할당 공간 생성                                           |
| **2. 설치 매체 준비** | Arch Linux ISO 다운로드 + 부팅용 USB 제작 (Rufus/balenaEtcher)                   |
| **3. USB로 부팅**  | F12로 부팅 메뉴 진입 → USB 선택해서 Arch 라이브 환경 진입                                 |
| **4. Arch 설치**  | 미할당 공간에 파티션 나누기 → 포맷/마운트 → 베이스 시스템 설치 → 부트로더(GRUB)를 **디스크 1의 MBR에만** 설치 |
| **5. 확인 & 마무리** | 재부팅 → F12로 디스크 1 선택해서 Arch 정상 부팅 확인 → 윈도우도 그대로 디스크 0으로 잘 뜨는지 확인         |

핵심은 4번 단계에서 "GRUB을 디스크 0(윈도우)이 아니라 디스크 1에만 설치"하는 부분이고, 그 이후엔 네트워크 연결, 데스크톱 환경(선택사항) 등 세부 설정이 이어져요. 큰 그림은 이 정도고, 실제로 손 댈 일은 1~4단계입니다.

### 지금 당장 할 것: 0단계 + 1단계 세밀 안내

#### 0단계 — 사전 준비 (설치 전 딱 한 번만)

1. ~~**그림 작업물/중요 파일 백업**: SAI 작업 파일, 문서 등을 외부 SSD(또는 클라우드)에 복사해두기. (이미 하셨으면 패스)~~
2. **윈도우 복구 USB 만들기**: 여유 USB(8GB 이상) 하나 꽂고
    - 윈도우 검색창에 `복구 드라이브 만들기` 검색 → 실행
    - "시스템 파일을 복구 드라이브에 백업" 체크 → 다음 → USB 선택 → 만들기
    - 이걸로 만약 나중에 윈도우 부팅에 문제가 생겨도 이 USB로 복구 가능

#### 1단계 — F: 드라이브 볼륨 축소

1. `Win + X` → **디스크 관리** 클릭
2. 아래쪽 디스크 1(931GB, F:) 파티션 막대를 **우클릭** → **볼륨 축소**
3. "축소할 공간(MB)" 입력란에 숫자 입력
    - MB 단위라서 헷갈리기 쉬운데, **100GB를 원하면 102400 입력** (100 × 1024)
    - 처음이니 넉넉하게 **120000~150000 (약 120~150GB)** 정도 추천 — Arch 루트 파티션 + 나중에 이것저것 설치할 여유분
4. **축소** 버튼 클릭 → 잠시 기다리면 F: 파티션 뒤쪽에 **"미할당" (검은색)** 공간이 생김
5. 이 미할당 공간은 **그대로 두고 아무것도 하지 마세요** (포맷하거나 새 드라이브 문자 할당하지 말 것 — Arch 설치 프로그램이 이 빈 공간을 직접 잡아서 파티션을 나눌 거예요)

축소 끝나고 미할당 공간 생성된 거 확인되면 알려주세요. 그러면 2단계(Arch ISO 다운로드 + 부팅 USB 제작)로 넘어갈게요.
