
# CPU GHz

컴퓨터 세상에서 기가헤르츠($GHz$)는 클럭 속도(Clock Speed)를 의미하는 단위인데요, 아주 직관적으로 쪼개서 설명해 드릴게요.

### 1. 3.00GHz의 진짜 의미

- **Hz (헤르츠):** 1초에 1번 연산(진동)한다는 뜻입니다.
- **MHz (메가헤르츠):** 1초에 100만 번 연산합니다.
- **GHz (기가헤르츠):** 1초에 **10억 번** 연산합니다.

> 즉, **3.00GHz**라는 것은 이 CPU가 **1초 동안 무려 30억 번의 전기 신호(싸이클)를 주고받으며 데이터를 처리할 수 있다**는 뜻입니다. 숫자가 높을수록 1초에 처리하는 일의 양이 많아지니 당연히 속도가 빨라지겠죠?

### 2. 왜 내 컴퓨터는 3.00GHz인데 느릴까? (중요!)

"어? 1초에 30억 번이나 일하면 엄청 빠른 거 아냐?" 싶으실 텐데요. 여기에 컴퓨터의 함정이 있습니다. 성능은 이 속도가 전부가 아니라 **'코어(Core)'의 개수**와 '아키텍처(설계 구조)'가 같이 받쳐줘야 합니다.

이해하기 쉽게 '수학 문제를 푸는 사람'으로 비유해 볼게요.

- **3.00GHz:** 받아 적고 계산하는 손발이 얼마나 빠른가 (작업 속도)
- **코어(Core) 수:** 문제를 푸는 사람이 몇 명인가 (일손)
- **세대(설계):** 이 사람이 초등학생인가, 대학생인가 (지능)

사용자님의 **i5-7400 CPU**는 기본 속도가 3.00GHz이고, 사람(코어)이 4명 있는 상태입니다. (7400 = 모델명이긴 한데 7=출생 세대(17년 출시), 400<500<600 이런느낌)


하지만 2017년에 나온 모델이라 '지능(설계)' 자체가 옛날 기준입니다. 요즘 나오는 최신 CPU는 같은 3.00GHz라 하더라도 초등학생이 아니라 **대학생 10~20명이 모여서 문제를 푸는 격**이라 비교가 안 될 정도로 빠릅니다.

### 요약하자면

3.00GHz는 CPU의 순수한 발걸음 속도(1초에 30억 번)를 말하지만, 컴퓨터가 진짜 빠른지 보려면 몇 년도에 나왔는지(세대)와 사람이 몇 명인지(코어 수)를 함께 봐야 진짜 성능을 알 수 있습니다!


# PC 사양

2026년 현재 전 세계 게이머들이 가장 많이 쓰는 PC의 '평균 사양(스팀 하드웨어 통계 기준)'과 사용자님의 사양을 부품별로 직관적으로 비교해 드릴게요.

결론부터 말씀드리면, 지금 평균 사양은 사용자님 컴퓨터보다 **적게는 3배, 많게는 5배 이상** 앞서 있는 상태입니다.

### 부품별 평균 vs 내 컴퓨터 비교

| **부품**        | **현재 전 세계 평균 사양**          | **사용자님의 사양**              | **얼마나 차이 날까?**                                            |
| ------------- | -------------------------- | ------------------------- | --------------------------------------------------------- |
| **CPU**       | 6코어 ~ 8코어 (주로 6코어)         | **4코어** (i5-7400)         | 머릿수도 부족하고 지능(세대) 차이가 심해 **처리 속도가 3배 이상** 차이 납니다.          |
| **그래픽 (GPU)** | RTX 3060 / RTX 4060급       | **GTX 1050**              | 게임 그래픽을 그려내는 능력이 **최소 4~5배 이상** 차이 납니다.                   |
| **램 (RAM)**   | **16GB** (최근 32GB 급성장 중)   | **8GB**                   | 작업대 크기가 정확히 **절반 이하**라 멀티태스킹이 힘듭니다.                       |
| **용량 (SSD)**  | **1,000GB (1TB) NVMe SSD** | **110GB SSD** + 931GB HDD | 메인 드라이브 용량이 **9배** 작고, 게임을 저장하는 HDD는 속도가 **10배 이상 느립니다.** |

### 조금 더 체감되게 설명해 드리면요,

- **평균 PC의 성능:** 요즘 피시방이나 일반적인 게이밍 PC의 표준입니다. _배틀그라운드_, _로스트아크_, _팰월드_ 같은 대중적인 게임들을 상옵~풀옵으로 아주 부드럽게(100프레임 이상) 돌릴 수 있는 수준입니다.

- **사용자님 PC의 성능:** 롤, 서든어택, 피파 온라인 같은 저사양 게임은 하옵으로 겨우 방어가 되지만, 평균 사양의 PC가 가볍게 돌리는 요즘 게임들은 켜는 것조차 버겁거나 렉이 심하게 걸리는 상태입니다.

즉, 지금 평균 사양과 비교하면 사용자님의 컴퓨터는 **체급 자체가 완전히 밀리는 구형 보급형 PC**라고 볼 수 있습니다.



# Format

포맷(Format)은 컴퓨터나 전자기기에서 쉽게 말해 "저장 장치를 완전히 초기화하고, 
새로운 데이터를 담을 수 있도록 바닥 공사를 다시 하는 것"을 말합니다.

### 1. 가장 쉬운 비유: 새 공책 만들기

낙서가 가득 차서 더 이상 쓸 공간이 없거나, 군데군데 찢어져서 지저분해진 공책이 있다고 해볼게요.

- 지우개로 글씨를 하나하나 지우는 건 '일반적인 삭제'입니다. (흔적이 남거나 시간이 오래 걸리죠.)

- **포맷**은 그 공책의 모든 페이지를 싹 뜯어내고, 언제든 새 글을 깔끔하게 쓸 수 있도록 완전한 새 공책 상태(공장 출고 상태)로 만드는 것입니다.


### 2. 포맷을 하면 실제로 일어나는 일

포맷을 진행하면 컴퓨터 내부에서는 크게 두 가지 작업이 일어납니다.

- **데이터 완전 초기화:** 사진, 동영상, 게임, 문서 등 저장 장치(SSD나 HDD, USB 등)에 들어있던 모든 파일이 사라집니다.

- **파일 시스템 구축 (방 나누기):** 데이터를 그냥 무작위로 던져두면 컴퓨터가 찾지 못하겠죠? 컴퓨터가 데이터를 질서 있게 저장하고 읽을 수 있도록 책장의 칸을 나누는 규칙(**파일 시스템**)을 새로 설정합니다.


### 3. 포맷은 주로 언제 할까?

보통 다음과 같은 답답한 상황이 생겼을 때 '최후의 수단'이자 '가장 확실한 해결책'으로 사용합니다.

- **컴퓨터가 너무 느려졌을 때:** 오랫동안 쌓인 찌꺼기 파일과 프로그램 오류를 한 방에 청소하고 싶을 때

- **바이러스나 악성코드에 감염됐을 때:** 백신으로도 치료가 안 되는 심각한 오류가 발생했을 때

- **PC나 스마트폰을 남에게 팔거나 버릴 때:** 내 개인정보가 유출되지 않도록 깨끗이 지워야 할 때


> ⚠️ **포맷 전 필수 주의사항!** 포맷은 방을 청소하는 수준이 아니라 **'건물을 허물고 다시 짓는 수준'** 입니다. 포맷을 누르는 순간 중요한 사진이나 파일은 모두 복구하기 어려워지므로, 반드시 중요한 데이터는 미리 **백업(다른 USB나 클라우드에 따로 저장)** 해 두어야 합니다.





# UEFI

**UEFI**는 쉽게 말해서 "컴퓨터 전원을 켰을 때, 윈도우가 켜지기 전까지 컴퓨터를 지휘하는 아주 똑똑한 최신형 지휘관"입니다.

기존에 수십 년간 사용하던 Legacy BIOS(바이오스)라는 늙은 지휘관의 뒤를 이어받은 세대교체 주인공인데요. 두 지휘관의 차이를 보면 UEFI가 왜 필요한지 바로 이해되실 겁니다.

### 1. 직관적인 비교: BIOS vs UEFI

컴퓨터 전원을 켜면 윈도우 로고가 뜨기 전에 파란 화면이나 검은 화면에 영어 가득한 설정 창으로 들어갈 때가 있죠? 그 화면의 정체가 바로 이겁니다.

- **Legacy BIOS (과거의 지휘관):**
    
    - 마우스를 못 쓰고 오직 **키보드 방향키**로만 조작해야 했습니다.
    
    - 디자인도 투박한 파란색/검은색 화면이었습니다.
    
    - 옛날 방식이라 부팅 속도가 느리고, 앞서 말씀드린 **2TB 이상의 큰 하드디스크(GPT 방식)를 인식하지 못했습니다.**


- **UEFI (현재의 지휘관):**
    
    - **마우스 클릭**이 가능하고, 화려한 그래픽 인터페이스를 지원합니다. (한국어를 지원하는 경우도 많습니다.)
    
    - 주소록을 넓게 쓰는 **GPT 방식을 완벽하게 지원**해서 3TB, 4TB 이상의 대용량 디스크로도 부팅할 수 있습니다.
    
    - 컴퓨터 부품들을 동시에 빠르게 검사하기 때문에 **부팅 속도가 압도적으로 빠릅니다.**


### 2. UEFI가 왜 중요할까?

단순히 화면이 예뻐지고 마우스를 쓸 수 있어서 좋은 것만은 아닙니다. 
핵심은 '보단 안전하고, 빠르고, 큰 디스크를 쓰기 위함'입니다.

- **보안 (Secure Boot):** 컴퓨터가 켜질 때 해킹 프로그램이나 악성코드가 먼저 침투하는 것을 원천 차단하는 강력한 보안 기능이 들어있습니다.

- **윈도우 11의 필수 조건:** 마이크로소프트는 **윈도우 11부터 UEFI 방식을 필수로 요구**합니다. 컴퓨터 메인보드가 UEFI를 지원하지 않거나 끈 상태라면 윈도우 11 설치가 불가능합니다.


### 3. 지금까지 이야기의 연결고리

질문하셨던 내용들이 결국 다 하나의 세트로 이어지는 개념입니다.

- **과거 조합:** `Legacy BIOS` 지휘관 + `MBR` 땅문서 (2TB 용량 제한, 느린 부팅)

- **현대 조합:** `UEFI` 지휘관 + `GPT` 땅문서 (대용량 지원, 초고속 부팅, 윈도우 11 필수)


요즘 컴퓨터를 포맷하고 새로 세팅할 때는 무조건 **UEFI + GPT 조합**으로 간다고 생각하시면 됩니다! (디스크가 작은 노트북들은 BIOS 가 나오는 거처럼 보이는데, 사실 BIOS 라는 이름이 널리 퍼져있어서 BIOS를 달고 나오는 UEFI라고 함.)



# Disk MBR, GPT

**MBR**과 **GPT**는 쉽게 말해 "디스크의 땅문서(또는 주소록)를 작성하는 두 가지 방식"입니다. 저장 장치에 방을 어떻게 나누고(파티션), 부팅 정보는 어디에 둘지 결정하는 규칙인데요.

두 방식의 차이점을 가장 핵심적인 부분만 깔끔하게 비교해 드릴게요.

### 1. 한눈에 보는 핵심 차이점

|구분|MBR (Master Boot Record)|GPT (GUID Partition Table)|
|---|---|---|
|**등장 시기**|1983년 (옛날 방식)|2000년대 이후 (최신 방식)|
|**최대 인식 용량**|**2TB (테라바이트)** 이하만 가능|**제한 없음** (사실상 무한)|
|**최대 파티션 개수**|방을 최대 **4개**까지만 쪼갤 수 있음|방을 최대 **128개**까지 쪼갤 수 있음|
|**안정성 (복구)**|부팅 정보가 한 곳에만 있어 깨지면 끝|부팅 정보를 여러 곳에 백업해 둬서 안전함|
|**메인보드 호환성**|옛날 컴퓨터 (BIOS 방식)|요즘 컴퓨터 (UEFI 방식)|

### 2. 왜 MBR에서 GPT로 바뀌었을까? (결정적인 이유 2가지)

#### ① "2TB 벽"에 부딪힌 MBR

MBR은 40년도 더 전에 만들어진 규칙이라, 당시에는 '테라바이트(TB)' 단위의 거대한 하드디스크가 나올 거라고 상상도 못 했습니다. 그래서 MBR 방식을 쓰면 **3TB짜리 하드디스크를 꽂아도 컴퓨터가 2TB까지만 인식하고 나머지 1TB는 버려지게 됩니다.** 이 한계를 깨기 위해 나온 게 GPT입니다.

#### ② 윈도우 11의 등장

컴퓨터의 기본 부팅 시스템이 옛날 방식(BIOS)에서 최신 방식(UEFI)으로 세대교체가 되었습니다. 특히 **윈도우 11부터는 보안과 안정성 때문에 무조건 GPT 방식을 요구**합니다. MBR 방식으로 설정된 디스크에는 윈도우 11을 정상적으로 설치할 수 없습니다.
(그래서 PC가 윈도우 10인 것일듯..)

### 💡 요약하자면

- 내가 쓰는 저장 장치가 **2TB 이하**이고 아주 오래된 컴퓨터라면 **MBR**을 써도 무방합니다.

- 하지만 **대용량 SSD/HDD**를 쓰거나, **윈도우 10/11** 환경이라면 고민할 필요 없이 **GPT**를 선택하시는 것이 무조건 좋습니다. 최근에 맞춘 컴퓨터라면 사실상 GPT가 기본 표준입니다.



# CPU socket 

CPU 소켓(Socket)은 쉽게 말해 메인보드(베이스보드)에 뚫려 있는 "CPU 전용 주차 공간"이자 "콘센트 구멍"입니다.

CPU 밑바닥을 보면 전기 신호를 주고받기 위해 수천 개의 아주 미세한 바늘(핀)이나 **금색 접점**이 빽빽하게 박혀 있거든요. 이 구멍과 핀이 자석처럼 자리가 딱 맞아떨어져야만 CPU를 장착할 수 있습니다.

하위 호환성이 전혀 없어서 조립할 때 우리를 가장 킹받게 만드는 주범이기도 합니다.

### 1. 두 회사의 소켓 방식 (인텔 vs AMD)

인텔과 AMD는 CPU 소켓을 만드는 방식이 서로 다릅니다. 이 방식 때문에 모양도 완전히 다르게 생겼죠.

- **LGA (Land Grid Array) 방식 — 주로 인텔 / 최신 AMD**
    
    - **핀(바늘)이 메인보드 소켓에 달려 있습니다.** CPU 밑바닥은 매끈한 금색 점들만 있죠.
    
    - 실수로 보드 소켓을 핀셋 같은 걸로 찌르면 바늘이 휘어서 보드가 고장 나기 때문에 장착할 때 손을 벌벌 떨게 만드는 방식입니다.

- **PGA (Pin Grid Array) 방식 — 과거 AMD**
    
    - **핀(바늘)이 CPU에 달려 있습니다.** 메인보드 소켓에는 구멍만 뚫려 있죠.
    
    - 쿨러를 떼어낼 때 CPU가 껌처럼 딱 붙어서 같이 뽑히는 '무뽑기 현상'으로 유명했던 방식입니다.
    

### 2. 소켓 이름 뒤에 붙는 숫자의 비밀

보통 메인보드 박스나 사양표를 보면 **`소켓 LGA1700`**, **`소켓 AM5`** 같은 이름이 적혀 있습니다. 이게 무슨 뜻이냐면요.

- **LGA1700 (인텔):** "이 메인보드 소켓에는 1,700개의 바늘(핀)이 있으니까, 접점이 똑같이 1,700개인 인텔 CPU만 가져와라"라는 뜻입니다. (숫자가 곧 핀 개수입니다.)

- **AM5 (AMD):** AMD는 숫자가 아니라 세대 이름을 붙입니다. "우리의 5세대 규격 소켓이니까 여기 맞는 CPU만 꽂아라"라는 뜻이죠.


### 3. 왜 세대마다 소켓을 바꿀까? (하위 호환성이 없는 이유)

많은 조립러들이 "소켓 구멍 좀 그냥 똑같이 유지해 주면 안 되냐?"라고 분통을 터뜨립니다. 제조사들이 소켓을 바꾸는 이유는 **CPU의 기술 발전** 때문입니다.

새로운 CPU가 나올 때마다 성능이 엄청나게 좋아지면서 **전기도 더 많이 먹고, 데이터가 지나다니는 길(대역폭)도 훨씬 넓어져야 합니다.** 그러려면 당연히 메인보드와 연결되는 전선(핀)의 개수가 더 많이 필요하겠죠?

예를 들어 인텔 11세대 소켓은 핀이 1,200개였는데, 성능이 대폭 올라간 12세대부터는 1,700개로 늘어났습니다. 핀 개수와 크기가 달라지니 옛날 메인보드 구멍에는 물리적으로 들어갈 수가 없게 되는 것입니다.

> **💡 핵심 요약** CPU 소켓은 CPU를 꽂는 **구멍 규격**이다. 모양과 핀 개수가 단 1개만 달라도 아예 장착이 불가능하므로, 메인보드를 살 때는 내가 고른 CPU의 **소켓 이름**과 정확히 일치하는지 무조건 확인해야 합니다!

## AMD, MIPS, etc..

### 1. AMD 

앞서 인텔과 함께 소켓 이야기할 때 나온 AMD(Advanced Micro Devices)는 인텔과 경쟁하는 **세계적인 CPU 및 그래픽카드 제조 회사** 이름입니다.

- 인텔이 독점하다시피 하던 CPU 시장에서 '라이젠(Ryzen)'이라는 메가 히트작 시리즈를 터뜨리며 인텔의 멱살을 잡고 싸우고 있는 고마운 경쟁사죠.

- 우리가 쓰는 일반 컴퓨터(PC, 노트북)의 CPU는 전 세계에서 인텔(Intel)과 **AMD** 딱 두 회사 제품만 쓴다고 생각하시면 됩니다.


### 2. MIPS


- **MIPS**는 회사가 아니라 CPU를 설계하는 방식, 즉 **명령어 집합 아키텍처(ISA)** 구조 중 하나입니다.

- 전공 필수 과목인 **'컴퓨터 구조(Computer Architecture)'** 교과서(가장 유명한 패터슨 저서의 하얀색/검은색 표지 '컴퓨터 구조 및 설계' 책)에서 **실습용과 교육용 표준**으로 주구장창 배우는 설계도입니다.


> **왜 하필 MIPS로 배웠을까?**
> 
> 우리가 쓰는 인텔/AMD의 CPU 구조(x86)는 수십 년간 살이 붙어서 너무 복잡하고 지저분합니다. 반면, MIPS는 구조가 극단적으로 단순하고 규칙적이어서 **"컴퓨터가 명령어를 처리하는 기본 원리(RISC)"** 를 가르치기에 학부생 교육용으로 이만하게 없기 때문입니다.
> 
> 수업 시간에 주구장창 했던 `add`, `sub`, `lw`, `sw` 같은 어셈블리 명령어가 바로 MIPS 명령어입니다.

### 3. "그때 배운 아키텍처가 뭐였더라?" 후보군

기억이 가물가물하시다면, 대학교 CS 커리큘럼에서 다루는 아키텍처는 아래 3가지 중 하나입니다. 책 표지나 PPT 슬라이드를 떠올려 보세요!

1. **MIPS (가장 유력):** 방금 말씀드린 교육용 아키텍처의 대명사.

2. **ARM (암):** 요즘 대학교에서 MIPS 대신 엄청나게 많이 가르치는 구조입니다. 여러분이 쓰시는 스마트폰(갤럭시, 아이폰)과 애플 맥북에 들어가는 칩셋의 뿌리가 되는 아키텍처입니다.

3. **RISC-V (리스크 파이브):** 비교적 최근에 CS를 배우셨다면 오픈소스 아키텍처인 RISC-V 기반으로 배우셨을 수도 있습니다.

4. **x86 (인텔/AMD):** 실습용이라기보단 "우리가 쓰는 실제 PC는 이렇게 복잡한 구조란다" 하면서 비교 대상(CISC 구조)으로 배웠을 확률이 높습니다.


### 💡 깔끔하게 개념 연결하기

- **AMD / 인텔:** 우리가 실제로 돈 주고 사는 **컴퓨터 칩 제조 회사**
    
- **MIPS / ARM / x86:** 대학교 강의실과 연구소에서 배우는 **CPU의 설계 도면 양식 (아키텍처)**




# Baseboard (=Mainboard, Motherboard)

베이스보드(Baseboard)는 한마디로 
**컴퓨터의 '몸통'이자 모든 부품을 연결해 주는 '어머니' 같은 존재**입니다.

우리가 흔히 **메인보드(Mainboard)** 또는 마더보드(Motherboard)라고 부르는 바로 그 부품을 의미합니다. 컴퓨터 사양을 확인할 때 시스템 정보 창에서 공식 명칭으로 '베이스보드'라는 단어를 사용하기 때문에 낯설게 느껴지셨을 거예요.

결론부터 말씀드리면, **컴퓨터든 노트북이든 스마트폰이든, 전자기기라면 무조건 베이스보드가 들어있습니다.** 없으면 컴퓨터가 작동할 수 없거든요!

### 1. 베이스보드의 역할: "인체의 뼈대와 신경망"

컴퓨터의 핵심 부품들(CPU, 메모리, SSD, 그래픽카드 등)이 아무리 똑똑하고 빨라도, 
서로 대화를 나누지 못하면 아무 소용이 없겠죠?

베이스보드는 이 **모든 부품을 한곳에 꽂아서 튼튼하게 고정해주고, 부품들끼리 전기 신호(데이터)를 주고받을 수 있도록 길(회로)을 열어주는 역할**을 합니다. 사람으로 치면 모든 장기를 연결하는 뼈대와 척수 신경망인 셈입니다.


### 2. 노트북에도 당연히 베이스보드가 있나요?

**네, 당연히 있습니다. 심지어 노트북의 베이스보드는 데스크톱보다 훨씬 치밀하고 중요합니다.**

- **데스크톱 베이스보드:** 넓적한 판때기 모양으로 생겼고, 부품을 언제든 뺐다 꼈다 할 수 있도록 '소켓(플러그)'들이 많이 달려 있습니다.

- **노트북 베이스보드:** 두께를 얇게 만들고 무게를 줄여야 하므로, 부품을 꽂는 소켓을 과감히 없앴습니다. 대신 **CPU, 메모리, 심지어 그래픽카드까지 베이스보드 판 위에 아예 납땜(일체형)으로 박아버리는 경우**가 많습니다. 그래서 노트북은 베이스보드가 고장 나면 부품 하나만 바꾸기 힘들고 보드 전체를 갈아야 해서 수리비가 많이 나오는 편입니다.


### 3. 지금까지 질문하신 내용과의 연결고리

눈치채셨을지 모르겠지만, 지금까지 물어보신 개념들이 모두 이 **베이스보드** 위에서 일어나는 일들입니다.

- 컴퓨터 전원을 켜면 **베이스보드**에 내장된 최신형 지휘관(**UEFI**)이 깨어납니다.

- 그 지휘관이 **베이스보드**에 꽂혀 있는 SSD나 하드디스크의 땅문서(**GPT / MBR**)를 읽어서 윈도우를 부팅시키는 것이죠.

즉, 베이스보드는 이 모든 하드웨어와 소프트웨어가 살아 움직이는 '무대'라고 생각하시면 됩니다!

### 그럼 베이스보드 자체의 사양은? 조립 시 호환성은?

결론부터 말씀드리면, "기본형으로 쓸 거라면 호환성만 보면 되지만, 컴퓨터의 성능을 100% 쥐어짜거나 안정적으로 오래 쓰려면 사양이 아주 중요해진다"가 정답입니다.

왜 보드 사양을 따져야 하고, 호환성은 어디까지 봐야 하는지 핵심만 콕 짚어드릴게요.

### 1. 베이스보드 사양이 중요한 진짜 이유 (꽂는 판 그 이상인 이유)

#### ① 전원부의 품질 (CPU에 밥 주는 역할)

CPU는 일을 많이 할 때 엄청난 양의 전기를 끌어다 씁니다. 이때 파워서플라이에서 오는 가공되지 않은 거친 전기를 CPU가 먹을 수 있게 깨끗하고 안정적인 전기로 변환해 주는 장치가 베이스보드의 '전원부(VRM)'입니다.

- **싼 보드:** 전원부가 부실해서 고성능 CPU를 꽂으면 전력을 감당 못 해 CPU 속도를 강제로 낮춰버립니다(스토틀링 현상). 보드에 열이 펄펄 나다 수명이 깎이기도 합니다.

- **좋은 보드:** 전원부가 튼튼해서 CPU가 풀파워로 일해도 지치지 않고 안정적으로 전기를 공급합니다.


#### ② 확장성과 속도 규격 (대역폭)

똑같은 SSD나 그래픽카드를 꽂아도, 베이스보드가 지원하는 PCIe 버전(3.0 / 4.0 / 5.0)에 따라 데이터가 이동하는 고속도로의 속도가 달라집니다. 보드가 옛날 규격이면 아무리 최고급 SSD를 꽂아도 제 속도를 못 내고 반토막이 납니다. 그 외에 USB 포트 개수, 와이파이 내장 여부 등도 보드 사양에 갈립니다.


### 2. 호환성, 일일이 다 봐줘야 하나요?

**네, 슬프게도 조립할 때 가장 머리 아프게 호환성을 따져야 하는 부품이 바로 베이스보드입니다.** 아무거나 사면 아예 꽂히지도 않거든요. 딱 3가지만 체크하시면 됩니다.

#### ① CPU 소켓과 칩셋 (가장 중요)

인텔과 AMD는 당연히 서로 호환이 안 되고, 
같은 인텔 안에서도 세대마다 CPU 밑바닥의 핀 개수(소켓)가 다릅니다.

- _예: 인텔 14세대 CPU는 LGA1700 소켓을 쓰는 보드에만 장착 가능._

- 보드 상세 설명에 **"인텔 12/13/14세대 지원"** 혹은 **"AMD 라이젠 7000/9000시리즈 지원"** 같은 문구를 반드시 확인해야 합니다.

#### ② 램(RAM) 규격 (DDR4 vs DDR5)

요즘 과도기라 특히 조심해야 합니다. 내가 사려는 보드가 **DDR4 램**만 꽂을 수 있는 보드인지, 최신 **DDR5 램**을 꽂는 보드인지 확인하고 램을 세트로 맞춰야 합니다. 홈이 달라서 서로 교차 장착이 불가능합니다.

#### ③ 크기 규격 (폼팩터)

보드도 사이즈가 있습니다. 보통 큰 순서대로 **ATX, m-ATX, ITX**라고 부르는데, 내가 고른 컴퓨터 케이스 크기에 들어가는 사이즈인지 봐야 합니다. (보통 중간 크기인 `m-ATX`가 가장 무난하고 많이 쓰입니다.)

### 💡 요약하자면!

- **노트북은?** 제조사가 이미 호환성과 전원부를 완벽하게 맞춰서 일체형으로 만들어 놨으니 사용자가 호환성을 고민할 필요가 전혀 없습니다.

- **데스크톱 조립할 땐?**
    
    - 가성비 사무용 PC ➔ 부품들이 '장착되는지(호환성)'만 보고 제일 저렴한 보드 선택.
    
    - 고사양 게임/작업용 PC ➔ CPU와 그래픽카드가 제 성능을 낼 수 있도록 **전원부가 튼튼하고 PCIe 버전이 높은 중급 이상의 보드** 선택.

### 그래도 호환성 - 규격 이런걸 많이 타더라도 극심하지 않은 이유 => 하위호환성이라고볼수있나?

말씀하신 대로 규격이 복잡한데도 컴퓨터 조립 시장이 파국으로 치닫지 않고 유지되는 가장 큰 이유가 바로 **'하위 호환성(Backward Compatibility)'** 덕분입니다.

새로운 규격이 나오더라도 옛날 부품을 아예 못 쓰게 막는 게 아니라, "속도는 좀 떨어지더라도 일단 꽂으면 작동은 하게 해줄게"라는 배려가 깔려 있거든요.

이 하위 호환성이 가장 잘 적용되는 대표적인 부품들과, 반대로 절대 봐주지 않는 예외를 딱 정리해 드릴게요.

### 1. 하위 호환성의 타짜들: "꽂으면 일단 돌아간다"

#### ① 그래픽카드와 SSD (PCIe 규격)

컴퓨터 부품 중 하위 호환성이 가장 완벽한 곳이 바로 메인보드의 고속도로 규격인 PCIe(PCI Express)입니다.

- **상황:** 최신 PCIe 5.0을 지원하는 메인보드에, 옛날에 쓰던 PCIe 3.0 그래픽카드나 SSD를 꽂으면 어떻게 될까요?

- **결과:** 아무 문제 없이 잘 작동합니다. 반대로 옛날 메인보드(PCIe 3.0)에 최신 그래픽카드(PCIe 5.0)를 꽂아도 작동합니다. 다만 속도는 둘 중 **낮은 규격(3.0)에 맞춰 제한**될 뿐입니다. 모양과 규격이 바뀌어도 꽂는 홈(슬롯)은 그대로 유지하기 때문입니다.


#### ② USB 포트

외장하드나 마우스 등을 꽂는 USB도 하위 호환성의 끝판왕입니다. 최신 메인보드의 파란색 USB 3.2 포트에 15년 전 만든 USB 2.0 메모리를 꽂아도 속도만 느릴 뿐 데이터는 완벽하게 읽힙니다.

### 2. 하위 호환성 짤림: "절대 타협 없는 부품들"

하지만 메인보드 제조사들이 **"이건 절대 하위 호환 안 해줘, 새로 사!"** 하고 선을 긋는 핵심 부품이 2개 있습니다. 앞서 말씀드린 **CPU**와 램(RAM)입니다.

- **CPU (소켓 형태가 바뀜):** 세대가 바뀌면 CPU 밑바닥의 핀 배열이나 물리적인 크기 자체가 바뀝니다. 사각형이던 게 직사각형이 되기도 하죠. 애초에 물리적으로 장착이 안 되므로 하위 호환성이 0%입니다.

- **램 (홈의 위치가 바뀜):** DDR4 램과 DDR5 램은 가운데 파여 있는 홈(물리적 키)의 위치가 미세하게 다릅니다. 옛날 램을 최신 보드에 억지로 꽂으려고 하면 부서집니다. 전압과 데이터 처리 방식이 아예 달라서 메인보드가 하드웨어적으로 막아둔 것입니다.


### 💡 요약하자면

사용자가 조립할 때 극심한 스트레스를 받지 않는 이유는, **CPU와 램 규격** 이 두 가지만 메인보드와 세트로 맞춰두면, **나머지 부품(SSD, 그래픽카드, 파워서플라이, 케이스 등)은 하위 호환성 덕분에 대충 꽂아도 알아서 호환**되기 때문입니다.

판을 새로 짤 때 머리 아픈 영역을 딱 두 부품으로만 압축해 준 셈이죠!





# Programming Language

"언어로 언어를 만드는 것"을 프로그래밍 세상에서는 부트스트래핑(Bootstrapping)이라고 부르며, 실제로 지금 사용되는 거의 모든 언어가 이런 역사를 거쳐 만들어졌습니다.

질문자님이 정리하신 기계어 $\rightarrow$ 어셈블리어 $\rightarrow$ 고수준 언어의 흐름이 정확히 맞으며, 
메이저 언어들이 무엇으로 만들어졌는지 그 계보와 원리를 깔끔하게 정리해 드릴게요.

### 1. 메이저 언어들은 무엇으로 만들어졌을까?

결론부터 말씀드리면, 현대의 수많은 언어(파이썬, 자바, JS 등)를 지탱하는 뿌리는 C / C++입니다.

| **메이저 <br>언어** | **언어를 만드는 데 쓰인 언어            (컴파일러/인터프리터 엔진)** | **비고**                                      |
| -------------- | ---------------------------------------------- | ------------------------------------------- |
| **C**          | **어셈블리어(Assembly)** $\rightarrow$ **C 자체**     | 최초의 C 컴파일러는 어셈블리어로 작성됨                      |
| **C++**        | **C** $\rightarrow$ **C++ 자체**                 | 초창기 C++(C with Classes)은 C 코드로 변환해 주는 변환기였음 |
| **Python**     | **C** (CPython 구현체)                            | 우리가 쓰는 파이썬 표준이 바로 C로 만든 `CPython`           |
| **Java**       | **C / C++** (JVM 엔진)                           | 자바 실행 엔진(JVM) 자체가 C/C++로 만들어짐               |
| **JavaScript** | **C++** (V8 엔진 등)                              | 크롬 브라우저의 JS 엔진(V8)이 C++로 작성됨                |
| **Rust**       | **OCaml** $\rightarrow$ **Rust 자체**            | 최초의 Rust 컴파일러는 OCaml로, 현재는 Rust로 작성됨        |
| **Go**         | **C** $\rightarrow$ **Go 자체**                  | 초창기엔 C로 만들었다가 Go 1.5 버전부터 Go로 재작성함          |

### 2. "닭이 먼저냐, 계란이 먼저냐?" (부트스트래핑의 원리)

"아니, C언어가 없던 시절에 C언어 컴파일러를 어떻게 C언어로 만듦?" 이라는 의문이 드실 겁니다. 이 신기한 과정은 이렇게 진행됩니다.

```
[1단계] 기계어(010101...)를 사람이 읽기 쉽게 어셈블리어로 일대일 매핑
[2단계] 어셈블리어로 아주 기초적인 최소한의 'C언어 컴파일러 (v0.1)'를 만듦
[3단계] 이제 'C언어 (v0.1)'를 사용할 수 있게 됨!
[4단계] 이 'C언어 (v0.1)'를 사용해서 더 기능이 많은 'C언어 컴파일러 (v1.0)' 소스 코드를 작성함 (레고 블럭 조립해서 큰 블럭을 또 블럭으로 쓰듯이 재귀적으로 쓰는 느낌일듯)
[5단계] v0.1 컴파일러로 v1.0 소스 코드를 컴파일해서 'C언어 (v1.0)'를 완성함!
```

이 과정을 거치고 나면, **C언어로 작성된 코드 자기 자신을 C언어 컴파일러가 빌드하는 단계**에 도달합니다. 이를 **자승(Self-hosting)** 컴파일러라고 부르며, 현대의 C, C++, Rust, Go 등 정적 타입 언어들은 전부 자기 자신으로 스스로를 컴파일합니다.
