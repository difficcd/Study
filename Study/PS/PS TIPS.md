### PS TIP : 투 포인터, 슬라이딩 윈도우

알고리즘 작성 시 **무한 루프를 방지하고 깔끔한 코드를 유지하는 디버깅 꿀팁 3가지** 정리해 줄게!

**1. `while` 기반보다는 `for` 기반 슬라이딩 윈도우 구조 사용**

- `while(l < N && r < N)` 구조는 루프 안에서 `l++`, `r++`를 여러 조건 분기마다 직접 조작해야 해서 경계 조건 오버플로우나 무한 루프가 쉽게 발생해.
    
- 반면 `for(int r = 0; r < N; r++)`로 우측 포인터를 고정 전진시키고, 내부 `while`로 좌측 포인터(`l`)만 조절하면 **무한 루프 가능성이 구조적으로 차단**돼.
    

**2. `#ifndef ONLINE_JUDGE` 디버깅 패턴**

- 코테 제출 사이트(프로그래머스/백준 등)는 `ONLINE_JUDGE`라는 매크로를 내부적으로 정의해 둬.
    
- 아래처럼 매크로 블록을 만들어두면, 디버깅 출력을 코드에 그대로 남겨둔 채 제출해도 **제출 시에는 해당 코드가 아예 컴파일에서 제외**돼서 코드를 더럽히거나 지울 필요가 없어.
    

```C++
#ifndef ONLINE_JUDGE
    #define DEBUG(x) cout << #x << ": " << x << endl
#else
    #define DEBUG(x)
#endif

// 사용 시:
DEBUG(sum); // 제출할 때 지우지 않아도 자동 무시됨
```

**3. 단조성(Monotonicity) 체크 루틴**

- 투 포인터나 슬라이딩 윈도우에서 무한 루프가 나는 가장 큰 이유는 **포인터가 제자리에 멈춰있거나 양쪽 다 이동하는 상황** 때문이야.
    
- 로직을 설계할 때 "한 루프 회차에서 무조건 `l` 또는 `r` 중 단 하나는 전진하는가?"를 먼저 검증하면 `cout`을 수십 번 찍어보지 않아도 무한 루프를 예방할 수 있어.




### 📏 PS 자료형 선택 가이드 (범위별 팁)

- **$10^9$ (10억) 근처 또는 그 이상의 값이 예상될 때**
    
    - **무조건 `long long` 사용:** `int`의 최대 표현 범위는 약 $2 \times 10^9$ 이기 때문에, 연산 과정에서 값이 조금만 더 커지거나 곱해지면 오버플로우(Overflow)가 발생하여 쓰레기 값이 들어가게 됨.
        
- **자료형 혼용 주의**
    
    - `int`와 `long long`을 섞어서 쓰면 은근히 잡기 힘든 타입 캐스팅 에러나 오버플로우가 발생하기 쉬우므로, 값이 커질 여지가 있는 로직에서는 누적합, 계산 결과, 범위 변수 모두 `long long`으로 선언하는 것 추천



### 🚀 PS 고수들의 실전 디버깅 꿀팁

그래도 막상 꼬였을 때 `cout`을 쓰고 지우는 게 귀찮잖아요? 그럴 땐 고수들이 쓰는 **'조건부 디버깅(매크로)'** 방식을 추천해요.

코드 맨 위에 아래처럼 매크로를 하나 만들어두는 거예요.

C++

```
#include <iostream>
using namespace std;

// 제출할 때는 이 줄을 주석 처리(//) 하거나 지우면 됨!
#define DEBUG 

#ifdef DEBUG
#define D(x) cout << "[DEBUG] " << #x << " = " << x << '\n'
#else
#define D(x)
#endif
```

- **사용법:** 코드를 짜다가 변수 값이 궁금하면 `D(temp);` 라고만 적어두면 돼요.
    
- **장점:** 나중에 제출할 때 일일이 `cout`을 찾아서 지울 필요 없이, 맨 위의 `#define DEBUG` 한 줄만 지우면 모든 디버깅 출력이 마법처럼 사라져서 엄청 안전하고 편해요!
