## 최소공배수 개념 도입 원리

#### 먼저 신호등 1개만 생각해보기

신호등 하나의 주기가 `cycle = G+Y+R`라고 하면, 이 신호등은

```
1초, 2초, ..., cycle초, cycle+1초, ...
```

이렇게 흘러가다가 `cycle`초가 지나면 **똑같은 패턴이 처음부터 반복**됩니다. 즉 시각 `t`에서의 신호 상태는 `t`가 아니라 `t를 cycle로 나눈 나머지`(위상, phase)에만 의존해요.

그래서 신호등 1개만 있다면 "노란불인 시각들의 집합"은 이렇게 생겼습니다:

```
{G+1, G+2, ..., G+Y} ∪ {G+1+cycle, G+2+cycle, ..., G+Y+cycle} ∪ {... +2*cycle} ∪ ...
```

즉 **cycle마다 한 번씩 노란불 구간이 통째로 복사되어 찍히는** 거예요.


#### 신호등이 여러 개면?

각 신호등 `j`는 자기만의 `cycle_j`를 가지고 있고, 각자 자기 주기마다 패턴을 반복합니다. 유저가 느낀 "얘네가 도달하는 데 공통된 뭔가가 있다"는 감이 바로 이겁니다 —

**신호등 1의 전체 패턴이 반복되는 주기 = `cycle_1`**  
**신호등 2의 전체 패턴이 반복되는 주기 = `cycle_2`**

이 두 신호등을 "동시에" 봤을 때, **두 패턴이 합쳐진 전체 그림이 다시 처음과 똑같아지는 시점**은 언제일까요? 그건 `cycle_1`의 배수이면서 **동시에** `cycle_2`의 배수인 시점, 즉 **두 수의 공통된 배수**일 때입니다.

예를 들어 `cycle_1 = 4`, `cycle_2 = 6`이라면:

- 신호등1 패턴: 4, 8, 12, 16, 20, 24 ... 마다 리셋
- 신호등2 패턴: 6, 12, 18, 24 ... 마다 리셋
- **둘 다 동시에 리셋되는 지점**: 12, 24, 36 ... → 이게 공통배수

12초 지점에서는 신호등1도 "3바퀴 돈 것"(4×3), 신호등2도 "2바퀴 돈 것"(6×2)이라 **두 신호등 다 시각 0(=시각 12)과 똑같은 상태**가 됩니다. 그리고 이후로는 이 전체 그림(신호등1+신호등2의 조합 패턴)이 12초마다 통째로 복사되어 반복돼요.

#### 왜 하필 "최소"공배수인가

공통배수는 12, 24, 36... 여러 개가 있지만, 그중 **가장 작은 것(=최소공배수, LCM)**을 기준으로 삼는 이유는:

- 만약 정답(모두 노란불인 시각)이 존재한다면, **반드시 첫 번째 LCM 구간(1초 ~ 12초) 안에 적어도 한 번은 나타납니다.** 왜냐면 그 이후 구간(13~24초)은 그냥 앞 구간이 복사-붙여넣기 된 것뿐이라, 앞에 없던 게 뒤에 새로 생기지 않거든요.
- 그러니까 **1부터 LCM까지만 확인하면 충분**하고, 거기서도 못 찾으면 그 뒤로 아무리 가도 영원히 안 나옵니다 → `-1` 확정.

#### 여러 개(3개, 5개...)로 확장하면

두 수의 LCM 구하는 원리를 그대로 확장해서, 세 개 이상이면 `LCM(a, b, c) = LCM(LCM(a,b), c)`처럼 **두 개씩 짝지어 순차적으로 계산**하면 됩니다. 코드에서도 이렇게 하고 있어요:

cpp

```cpp
long long period = 1;
for (auto& s : signals) {
    long long cycle = s[0] + s[1] + s[2];
    period = mylcm(period, cycle);   // 지금까지의 LCM과 새 cycle의 LCM
}
```

이렇게 하면 신호등이 5개여도, "이 5개가 다 함께 처음 상태로 돌아오는 가장 빠른 시점"이 정확히 계산됩니다.

#### 유저 직감이랑 연결

유저가 "수열이 n개 나오고 걔네가 도달하는 거에 공통된 배수 같은 게 있다"고 느낀 게 정확히 이 구조예요 — **각 신호등을 "자기 주기마다 반복되는 수열"로 보고, 그 수열들이 동시에 같은 상태로 되돌아가는 지점을 찾는 문제**로 재해석한 거죠. 그게 바로 LCM의 정의 그 자체입니다. 애매했던 건 "여러 수의 공통된 걸 어떻게 하나의 숫자로 뽑아내지?"라는 계산 방법 부분이었을 텐데, 그건 그냥 두 수씩 짝지어서 `GCD`를 거쳐 `LCM`을 구하고, 그 결과를 다음 수와 또 짝지어서 반복하면 되는 거예요.
## LCM 도출법 : LCM, GCD

```cpp
long long mygcd(long long a, long long b){ return b==0 ? a : mygcd(b, a%b); }
```

### 유클리드 호제법 원리

핵심 아이디어: **`gcd(a, b) = gcd(b, a % b)`**

왜 성립하냐면, `a`를 `b`로 나눈 나머지가 `r`이라고 하면 (`a = b*q + r`), 
`a`와 `b`의 공약수는 항상 `b`와 `r`의 공약수와 정확히 같습니다. 
그래서 큰 수의 GCD를 구하는 문제를 계속 더 작은 수의 GCD 문제로 줄여나갈 수 있어요.

예를 들어 `gcd(48, 18)`을 구한다면:

```
gcd(48, 18) = gcd(18, 48%18) = gcd(18, 12)
gcd(18, 12) = gcd(12, 18%12) = gcd(12, 6)
gcd(12, 6)  = gcd(6, 12%6)  = gcd(6, 0)
gcd(6, 0)   = 6   (b==0이면 a가 답)
```

`b`가 0이 되는 순간 그때의 `a`가 GCD입니다. 이게 코드의 `b==0 ? a : ...` 부분이에요.

### GCD에서 LCM으로

두 수의 곱은 항상 `GCD × LCM`과 같다는 성질이 있습니다:

```
a * b = gcd(a, b) * lcm(a, b)
```

그래서 GCD만 구하면 LCM은 그냥 나눗셈으로 나옵니다:

```cpp
long long mylcm(long long a, long long b){ return a / mygcd(a,b) * b; }
```

여기서 `a * b`를 먼저 안 하고 `a / gcd(a,b) * b`로 순서를 바꾼 이유는, `a*b`를 먼저 계산하면 값이 너무 커져서 오버플로우가 날 수 있는데(이 문제에서는 20 이하라 괜찮지만), `a`를 `gcd`로 먼저 나눠서 작게 만든 다음 곱하면 같은 값이면서 오버플로우 위험이 줄어들기 때문이에요.

### 이 문제에 적용하면

`period = mylcm(period, cycle)`을 신호등 개수만큼 반복하는 게, 결국 유클리드 호제법을 신호등 쌍마다 계속 돌려서 "다 함께 처음 상태로 돌아오는 시점"을 좁혀나가는 과정입니다. 재귀 호출 자체는 나눗셈 몇 번이면 끝나서 매우 빠르고요.

정리하면: **GCD는 유클리드 호제법으로 구하고, LCM은 그 GCD를 이용한 공식으로 유도**하는 아주 표준적인 조합이 이 코드에 그대로 쓰인 거예요.
# 두 큐 합 같게 만들기

처음 코드

```Cpp
#include <string>
#include <vector>
#include <deque>

using namespace std;

int solution(vector<int> queue1, vector<int> queue2) {
    int answer = 0;
    
    deque<int> dq1;
    deque<int> dq2;
    
    for (int i=0; i<queue1.size(); i++){
        dq1.push_back(queue1[i]);
        dq2.push_back(queue2[i]); 
    }
    
    while(1){
        long long sum1=0, sum2=0; 
        
        for(int i=0; i<dq1.size(); i++) 
            sum1 += (long long)dq1[i];
        
        for(int i=0; i<dq2.size(); i++) 
            sum2 += (long long)dq2[i];
        
        if(sum1 > sum2) {
            int temp = dq1.front();
            dq1.pop_front();
            dq2.push_back(temp);
        }
        else {
            int temp = dq2.front();
            dq2.pop_front();
            dq1.push_back(temp);
        }
        
        if(sum1 == sum2) break;
        if(dq1.empty() || dq2.empty()) {
            answer = -1;
            break;
        }
        
        answer++;
    }
    
    return answer;
}

```

### 💡 왜 $4N$ (또는 $3N$) 인가? (증명)

각 큐의 초기 길이가 $N$이라고 할 때, 한 원소가 거칠 수 있는 **가장 긴 여정**을 생각:

1. **`queue1`의 원소 $A$가 `queue2`로 넘어감:** $N$번 이동 (최대 $N$개 원소 이동)
    
2. **`queue2`에 있던 원래 원소들까지 전부 `queue1`로 넘어감:** $N$번 이동
    
3. **`queue2`로 넘어갔던 $A$가 다시 `queue1`로 돌아옴:** $N$번 이동
    
4. **`queue1`로 돌아온 $A$가 자기 원래 자리(맨 뒤)로 돌아감:** $N$번 이동
    

$$N + N + N + N = 4N$$

- 모든 원소가 원래 상태로 완전히 한 바퀴 돌아서 되돌아오는 데 필요한 최대 연산 횟수가 $4N$
    
- 이 $4N$번을 움직이는 동안 두 큐의 합이 같아지는 순간이 단 한 번도 없었다면, **앞으로 영원히 돌려도 절대 합을 같게 만들 수 없다**는 것이 수학적으로 증명됨.
    

### 🚨 `10e3` (10,000)으로 잡으면 안 됐던 이유

`10e3`은 $10 \times 10^3 = 10,000$ 

- 문제에서 `queue1`의 최대 길이 $N$은 300,000 (30만)
    
- 정답을 만들기 위해 실제로 **20만~50만 번**을 움직여야 하는 정당한 테스트 케이스들이 존재함.

# 하노이 탑 (복습)

### 1. 세 인자의 진짜 '역할'

함수 정의에서 세 인자는 고정된 장소가 아니라 **역할**입니다.

- `from`: 출발지 (지금 원판들이 있는 곳)
    
- `to`: **최종 목적지** (이번 작업에서 원판을 최종적으로 갖다 놓아야 할 곳)
    
- `via`: **경유지/임시 거점** (목적지로 가기 위해 잠시 치워두는 빈자리)
    

### 2. 왜 SWAP이 일어나는가? (목적지의 변화)

$N$개짜리 하노이의 탑을 푸는 메인 미션은 "1번 기둥에서 3번 기둥(`to`)으로 $N$개를 옮기는 것"입니다.

이 대미션을 수행하려면 **두 번의 서브 미션**으로 쪼개집니다:

#### 1단계: 상위 $N-1$개를 '치우는' 단계 (L)

- **목표:** 제일 큰 $N$번 원판을 3번(`to`)으로 보내려면, 위에 얹힌 $N-1$개를 **2번 기둥(`via`)에 전부 모아놔야** 합니다.
    
- **해당 서브 미션의 최종 목적지(`to` 역할):** 3번이 아니라 **2번기둥**입니다!
    
- 따라서 재귀 호출을 할 때, 원래의 `via`(2번)를 이 서브 미션의 **`to`(목적지)** 자리에 넣어서 호출해야 합니다.
    
    $$\text{hanoi}(N-1, \text{from}, \mathbf{via}, \mathbf{to})$$
    
    _(원래 `to`였던 3번 기둥은 이 순간만큼은 잠시 스쳐 지나가는 '경유지'로 떨어집니다.)_
    

#### 2단계: 가장 큰 원판 1개를 옮기는 단계 (V)

- 제일 큰 원판을 1번(`from`)에서 원래 목표였던 3번(`to`)으로 옮깁니다.
    

#### 3단계: 치워뒀던 $N-1$개를 '다시 얹는' 단계 (R)

- **목표:** 2번 기둥(`via`)에 치워뒀던 $N-1$개를 **3번 기둥(`to`)에 있는 큰 원판 위에 얹어야** 합니다.
    
- **해당 서브 미션의 출발지(`from` 역할):** 1번이 아니라 **2번기둥**입니다!
    
- 따라서 2번(`via`)에서 출발해서 원래 목적지인 `to`로 가야 하므로:
    
    $$\text{hanoi}(N-1, \mathbf{via}, \mathbf{to}, \mathbf{from})$$
    
    _(원래 `from`이었던 1번 기둥이 이번엔 경유지 역할을 하게 됩니다.)_
    

### 요약

|**서브 미션**|**출발지 (from)**|**목적지 (to)**|**경유지 (via)**|**이유**|
|---|---|---|---|---|
|**L: $N-1$개 치우기**|출발 기둥|**임시 기둥 (원래 via)**|**최종 기둥 (원래 to)**|$N-1$개의 목표가 임시 기둥이므로 `to`와 `via`가 Swap됨|
|**V: 1개 옮기기**|출발 기둥|**최종 기둥**|-|가장 큰 원판 이동|
|**R: $N-1$개 얹기**|**임시 기둥 (원래 via)**|**최종 기둥 (원래 to)**|**출발 기둥 (원래 from)**|임시 기둥에서 출발하므로 `from`과 `via`가 Swap됨|

"내가 지금 옮기려는 $N-1$개 묶음의 '진짜 목적지'가 어디인가?"를 추적해 보면 `to`와 `via`가 왜 매번 자리를 바꾸는지 명확하게 이해할 수 있습니다.

```Cpp
void hanoi(int n, int from, int to, int via) {
    if (n == 0) return;

    cout << from << " -> " << to << endl;

    hanoi(n - 1, via, to, from);
}
```

### 이떄 받은 피드백 전문 :

#### 1. `dfs` 함수 내부: 2중 `for`문과 `row` 관리 (`24~25줄`)

1D 배열 `board[row] = col`을 쓰기로 하셨다면, **`dfs`는 "몇 번째 행(row)에 퀸을 놓을지"만 관리**하면 됩니다.

- **문제점:** 현재 `for(i)`와 `for(j)`로 2중 루프를 돌고 있어서, 이미 지나온 행을 다시 훑는 구조가 되었습니다.
    
- **해결 팁:** `dfs`의 매개변수로 `int row` (현재 놓으려는 행 번호)를 하나 받으세요.
    
    - `for(i)`는 필요 없고, **`for(int col = 0; col < n; col++)` 단일 루프**만 돌면 됩니다.
        
    - 다음 재귀는 `dfs(..., row + 1)`로 호출하면 깔끔해집니다.
        

#### 2. `isOk` 대각선 조건식 (`16줄`)

대각선 체크 아이디어는 훌륭하지만, 절댓값 처리(`abs`)가 빠져있습니다.

- **`x - i == y - board[i]`의 허점:**
    
    - 이 식은 우하향 대각선(`\`)만 체크합니다.
        
    - 좌하향 대각선(`/`)도 체크하려면 두 좌표의 **행 차이(`abs(x - i)`)와 열 차이(`abs(y - board[i])`)가 같은지** 비교해야 합니다.
        
    - 예: `abs(x - i) == abs(y - board[i])`
        

#### 3. 아직 놓이지 않은 빈 칸 검사 (`14~15줄`)

`isOk` 내부 `for(i)` 문에서 `board[i] == -1` 인 칸(아직 퀸이 안 놓인 빈 행)까지 검사를 수행하면, `y == -1`이 아닌 이상 `board[i] == y` 조건에 걸리지 않겠지만 대각선 계산 시 `-1`이 들어가 원치 않는 값이 나올 수 있습니다.

- **해결 팁:** `if(board[i] != -1)` 인, **이미 퀸이 놓인 행들만 대상으로 검사**하도록 조건문 하나만 걸어주시면 완벽합니다.

```Cpp
#include <string>
#include <vector>

using namespace std;


bool isOk(int x, int y, vector<int> board){
    for(int i=0; i<board.size(); i++){
        if(board[i] != -1){
            if(board[i] == y) return false;
            if(abs(x-i) == abs(y-board[i])) return false;
        }
    }

}

void dfs(int &cnt, int c, int n, vector<int> &board){
    if (n == 0) { cnt++; return; }
    for(int i=0; i<board.size(); i++){
        if(board[i] == -1 && isOk(i,c,board)){
           board[i] = c;
           dfs(cnt, c+1, n-1, board);
           board[i] = -1;
        }
    }    
}

int solution(int n) {
    int answer = 0;

    vector<int> board(n, -1);
    dfs(answer, 0, n, board);
    
    return answer;
}
```

### 수정해야 할 포인트 (단 1가지)

현재 `dfs` 내부의 `for(int i=0; i<board.size(); i++)` 루프가 문제가 될 수 있습니다.

- **현재 코드의 동작:** 매 재귀 단계마다 모든 행(`i`)을 훑으면서 `board[i] == -1`인 빈 행을 찾아 퀸을 넣으려고 합니다.
    
- **발생하는 문제:** `c`가 증가함에 따라 **행(`row`)을 순서대로 지정해 주면 되는데**, 매번 전체 행을 검사하다 보니 불필요한 반복 탐색과 호출이 발생합니다.
    

### 해결 방법

`c`를 '현재 퀸을 놓을 행(row) 번호'로 생각하고, 루프에서는 '몇 번째 열(col)에 놓을지'만 돌려주시면 됩니다.


```Cpp
void dfs(int &cnt, int row, int n, vector<int> &board){
    // n개의 퀸을 모두 놓았으면 정답 카운트
    if (row == n) { cnt++; return; }

    // 현재 row 행에서 어떤 col(열)에 놓을지 결정하는 루프
    for(int col = 0; col < n; col++){
        if(isOk(row, col, board)){
            board[row] = col;          // [1] 방문(퀸 배치)
            dfs(cnt, row + 1, n, board); // [2] 다음 행으로 깊게 파고들기
            board[row] = -1;           // [3] 백트래킹(복구)
        }
    }    
}
```

## N-Queen bitmasking 으로 최종 최적화해보기 (덤)

N-Queen 문제에서 $1\text{D}$ 배열로 $O(N)$ 시간 동안 대각선과 열 충돌을 검사하던 로직을 비트 연산(Bitwise Operation)을 활용해 $O(1)$로 줄이는 최적화 테크닉입니다.

배열이나 반복문 없이 비트 플래그만으로 체스판의 상태를 관리하므로, $N=12 \sim 15$ 같은 범위에서 속도가 수십 배 이상 빨라집니다.

### 핵심 아이디어: 3개의 비트 플래그

N-Queen의 충돌 검사는 아래 3가지만 확인하면 끝납니다. 이 상태를 정수(Integer) 3개의 비트로 표현합니다.

- **`cols` (열 충돌):** 어떤 열(Column)에 퀸이 이미 놓였는지 저장하는 비트
    
- **`left_diag` (좌하향 대각선 `/`):** 퀸이 한 행 내려갈 때마다 **왼쪽으로 1비트 Shift(`<< 1`)**
    
- **`right_diag` (우하향 대각선 `\`):** 퀸이 한 행 내려갈 때마다 **오른쪽으로 1비트 Shift(`>> 1`)**
    

### 비트 연산 백트래킹의 4단계 공식

```Cpp
// all_ones: N개의 비트를 1로 채운 마스크 (N=4 이면 0b1111 = 15)
int all_ones = (1 << n) - 1;

void dfs(int cols, int left_diag, int right_diag, int &cnt) {
    // 1. 모든 열에 퀸이 다 놓인 경우 (종료 조건)
    if (cols == all_ones) {
        cnt++;
        return;
    }

    // 2. 현재 행에서 퀸을 놓을 수 있는 빈 자리(비트가 1인 곳) 구하기
    // (cols | left_diag | right_diag) 는 공격받는 자리들(1)
    // ~ 연산자로 반전시킨 후 all_ones와 AND하여 N 비트 안의 빈 자리만 추출
    int available_positions = all_ones & ~(cols | left_diag | right_diag);

    // 3. 빈 자리가 남아있는 동안 퀸을 하나씩 배치해 보며 재귀
    while (available_positions > 0) {
        // 가장 오른쪽의 1(놓을 수 있는 첫번째 빈 자리) 비트만 추출
        int p = available_positions & -available_positions;

        // 선택한 자리를 지우고 다음 탐색으로 비트 Shift하여 넘김
        available_positions -= p;
        dfs(cols | p, (left_diag | p) << 1, (right_diag | p) >> 1, cnt);
    }
}
```

### 핵심 비트 테크닉 원리

1. **`cols | left_diag | right_diag`**
    
    - 현재 행에서 세 방향(세로, 대각선2개)의 공격 범위에 포함된 칸을 `1`로 합칩니다.
        
2. **`available_positions = all_ones & ~(...)`**
    
    - 공격받는 칸(`1`)을 반전(`~`)시켜 "퀸을 놓을 수 있는 칸"을 `1`로 만듭니다.
        
3. **`p = available_positions & -available_positions`**
    
    - 2의 보수 성질을 이용해 가장 오른쪽에 있는 `1` 비트 하나만 빼냅니다. (`for`문으로 열을 탐색할 필요 없이 놓을 수 있는 칸으로 바로 이동)
        
4. **`(left_diag | p) << 1` & `(right_diag | p) >> 1`**
    
    - 다음 행으로 넘어갈 때 **대각선 공격 범위가 한 칸씩 좌/우로 이동하는 특성**을 비트 Shift 연산 단 한 번으로 처리합니다. 배열 조회가 없으므로 $O(1)$ 연산입니다.
        

### 성능 비교 ($N=12$ 기준)

- **일반 1D 배열 백트래킹:** `isOk()` 함수 호출 및 $O(N)$ 검사 루프 오버헤드 존재 ($\approx 100 \sim 200\text{ms}$)
    
- **비트마스킹 백트래킹:** 순수 비트 연산만 수행, 함수 호출 횟수 감소 ($\approx 1 \sim 5\text{ms}$)
    

배열 복사나 반복문 검사가 완전히 사라지고 CPU 레지스터 차원에서 비트 연산이 실행되기 때문에 **N-Queen을 C++로 구현할 수 있는 최강의 최적화 기법**입니다.
